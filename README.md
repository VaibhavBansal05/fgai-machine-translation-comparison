# English-to-French machine translation: four small models

This project answers ICT4403 Foundations of Generative AI Assignment 3. It compares a Transformer trained from scratch, fine-tuned mT5, and prompted LLaMA-family and Gemma decoder-only models on the **same** English-to-French test set. The assignment specification is `IA3_ICT4403_FGAI_Final.pdf`.

## Dataset

[OPUS Books, English-French](https://huggingface.co/datasets/Helsinki-NLP/opus_books), a public parallel corpus of aligned book text (127,085 available pairs in this configuration). The script removes empty, very short, long, and duplicate English entries; normalizes whitespace; shuffles with seed 42; filters for detected English source and French target; and takes 200 training, 20 validation, and 20 held-out test pairs by default. This matters because some rows in the source corpus have the language fields reversed. Split sizes and the test-set SHA-256 are recorded in `results/run_config.json`. Because this is older literary text, the test results do not represent modern conversational or specialist translation.

The dataset card permits personal, educational, and research use, but restricts commercial resale and mass redistribution. The script downloads it at run time; the corpus is not committed here. Cite OPUS if you reuse the data.

## Models and methods

| Name | Checkpoint / architecture | Method |
|---|---|---|
| basic | Small PyTorch encoder-decoder Transformer, built here | Train from scratch on the training split; shared 8,000-word vocabulary |
| mt5 | [google/mt5-small](https://huggingface.co/google/mt5-small) | Fine-tune on the same training split |
| llama | [TinyLlama/TinyLlama-1.1B-Chat-v1.0](https://huggingface.co/TinyLlama/TinyLlama-1.1B-Chat-v1.0), LLaMA architecture | Zero-shot translation prompt; no task training |
| gemma | [google/gemma-3-270m-it](https://huggingface.co/google/gemma-3-270m-it) | Same zero-shot translation prompt; no task training |

TinyLlama uses the LLaMA architecture but is **not** a Meta LLaMA checkpoint. This is a transparent resource-saving substitute. Gemma access requires accepting Google's model terms on Hugging Face and logging in using `hf auth login` before running. All four use greedy generation for the main comparison. The prompted models additionally generate two examples each at temperatures 0, 0.7, and 1.0 for the requested sampling-temperature analysis.

## Run

Use a GPU runtime such as Google Colab (T4 is suitable). CPU execution is possible but will be slow. Run these commands in a fresh runtime with internet access:

```bash
pip install -r requirements.txt
hf auth login               # needed for Gemma; accept its terms on the model page first
python run.py
```

For a short smoke run, use `python run.py --train 40 --val 5 --test 5 --basic-epochs 1 --mt5-epochs 1 --output /tmp/fgai_smoke`. These numbers are **not** comparable to the default full run. To rerun just one model, use `--models basic` (or `mt5`, `llama`, `gemma`) with the same split arguments. Each completed model writes its own JSON metrics and CSV translations, so a later run can continue after a runtime interruption. Do not combine outputs from different split settings; the summary checks the test-set hash.

`results/summary.md` contains BLEU, chrF, training time (where applicable), inference seconds per sentence, and exact parameter counts. `results/*_translations.csv` contains every test source, reference, and generated translation. `results/*_temperatures.csv` contains sampling examples. These files are generated by the run, not invented in advance. Commit them after a complete run to include the required results and samples on GitHub.

## Comparison and evaluation

BLEU and chrF are corpus-level SacreBLEU scores. All models translate identical test sentences, with a maximum of 40 new tokens and greedy decoding for scoring. The two encoder-decoder models receive supervised training on the same 200 pairs; the decoder-only models use the same zero-shot prompt. Training time for prompt-only models is not applicable. Inference timing is measured over the whole test set on the current device. Differences in pretraining, model size, tokenizer, and adaptation mean that score differences cannot be attributed to architecture alone.

The measured comparison is in [ANALYSIS.md](ANALYSIS.md), with the table and plot in `results/summary.md` and `results/scores.svg`. **TinyLlama** is the best-performing model in this small run by both chrF and BLEU. The scratch model and one-epoch mT5 are deliberately small teaching baselines, and their measured translations are poor.

## Qualitative and responsible-AI discussion

Examine several rows of each `results/*_translations.csv`, especially names, negation, numbers, gendered language, and culturally specific expressions. Mark omissions, invented details, changed meanings, and inappropriate renderings of sensitive text. These are possible failure types; they are **not claims of observed errors** until the generated rows have been inspected. Compare the temperature CSVs for fluency and meaning drift. Higher temperature changes randomness, not translation accuracy by design.

To reduce risk, use a human reviewer for sensitive domains, keep the source alongside each output, check numbers/names/negation, evaluate with more than one metric, add diverse contemporary test data, and allow users to flag harmful or incorrect translations. Literary data can contain outdated wording and representation, so this system should not be used without review for medical, legal, or safety-critical text.
